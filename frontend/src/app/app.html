How SchemaBridge AI Connects System A & System B

Step-by-step architectural guide on configuring SchemaBridge between your disparate systems

LIVE DATA FLOW:
[ System A (SE) ]
│
│ 1. Sends native payload (e.g. POST http://localhost:8080/api/projects/{appId}/apis/{apiId}/transform)
▼
[ SchemaBridge AI Gateway ]
├─ 2. Inbound Contract Validation (Strict JSON / OpenAPI schema check)
├─ 3. Pure Java Deterministic Transformation (<5ms runtime latency, ZERO LLM in hot path)
└─ 4. Outbound Contract Validation (Validates output matches System B structure)
│
│ 5. Forwards converted payload or returns to caller
▼
[ System B (CCP) Target URL ]
1. Design-Time Contract Setup (Setup & Schemas Tab) Import a sample JSON or JSON Schema for System A and System B. This defines the data contract (field names, types, formats). It is not real customer data; it is the blueprint.
2. Mapping & AI Assistance (Mapping Workspace Tab) SchemaBridge's 5-level pipeline matches fields automatically (Exact, Normalized, Type, Arrays, Defaults). You can add custom rules or use Aviator AI to convert plain English commands. Once satisfied, click Publish Version to freeze the deterministic transformation contract.
3. API Registration (API Registry Tab) Register the endpoints under your App (e.g. POST /api/v1/customers or GET /api/v1/customers/{id}) and point the downstream Target URL (e.g. https://ccp.enterprise.internal/v1/customers).
4. Runtime Invocation (Zero Code Changes in System B) Configure System A to send requests to SchemaBridge instead of System B. SchemaBridge converts the payload in real-time according to the approved rules and delivers the translated payload to System B.
